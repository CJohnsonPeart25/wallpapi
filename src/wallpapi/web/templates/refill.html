{# The refill indicator: one line saying what the background thread is doing. It is rendered on every state of the batch page, and base.css hides it behind a batch only while it has nothing to report: "Pool 0 of 500, refill not running" is the whole diagnosis, and without it an empty page and a dead thread look exactly alike. A plain line and not a poll: the numbers move slowly, the page is reloaded often, and htmx polling this would be a request a second for something nobody is watching. The last run says which of the two strategies made it (#13), because "fetching" says nothing about what: a pool that only ever grows at random is a pool with no favourites in the decision log yet, and that is something the person reading this line can do something about. #}
